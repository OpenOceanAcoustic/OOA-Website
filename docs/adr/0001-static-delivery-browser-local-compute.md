# 静态托管与浏览器本地计算

OOA Website 只发布静态页面、Worker 和 WASM 资源，所有实验环境解析与模型计算都在学习者的浏览器中完成。相比建设后端计算服务，这一选择减少运维和隐私负担，也允许教学实验使用学习者自己的 CPU 与内存；代价是网站必须明确设备能力、内存限制和运行失败，不能把输入上传到服务器或静默回退到伪造结果。

## Consequences

- 正常入口不得调用远程声场计算、数据库或环境文档上传接口。
- Bellhop2D、Kraken 和 RAM 的 WASM npm 包是生产计算的唯一来源。
- 教学演示必须由显式 `?demo` 入口启用，并与模型计算明确区分。
- 单线程 WASM 是兼容基线；HTTPS 加 COOP/COEP 后可使用模型包推荐的并行运行方式。
- 部署验收必须覆盖 WASM MIME、缓存、SPA fallback、跨源隔离头和真实浏览器计算。
